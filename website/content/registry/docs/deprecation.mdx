title: Deprecation & Deletion
description: Learn how to retire an asset reversibly (deprecation) or permanently (deletion).

There are two ways to retire an asset, and they differ in exactly one thing: whether you can change your mind later.

- **Deprecation** retires an asset _reversibly_. You can restore it at any time.
- **Deletion** retires an asset _permanently_. It can never be restored. Returning the content to the Registry would require publishing a new listing.

Everything else is the same. A deprecated or deleted asset:

- is _no longer downloadable_ from Railyard or the website;
- is _hidden from browse and search results by default_. Select its class in the _Status_ filter to see it, marked with its own badge and always sorted last;
- is _left otherwise unchanged_: the listing page, download history, and author attribution remain constant, and download counts stay credited to the author and/or caretakers.

|                                         | Deprecated                              | Deleted                              |
| --------------------------------------- | --------------------------------------- | ------------------------------------ |
| Downloadable                            | No                                      | No                                   |
| Visible in browse by default            | No (select _Deprecated_ under _Status_) | No (select _Deleted_ under _Status_) |
| History, credits & download counts kept | Yes                                     | Yes                                  |
| Reversible                              | **Yes**                                 | **No, permanent**                    |

## Who can deprecate or delete {#who-can-deprecate}

Only the asset's _original publisher_ or its _active [caretaker](/registry/docs/caretakers)_ can deprecate or delete it (or reverse a deprecation). Ordinary [collaborators](/registry/docs/collaborators) cannot.

## How to deprecate an asset {#how-to-deprecate}

1. On the [Registry's GitHub repository](https://github.com/Subway-Builder-Modded/registry), navigate to **Issues** > **New Issue** > **Deprecate an Asset**.
2. Enter the _asset ID_. The form works for both mods and maps, so no type selection is needed.
3. Optionally provide a _reason_ (e.g. "Superseded by my-asset-2"). It is shown publicly on the asset's listing page.
4. Submit. After validation confirms the requester is the publisher or active caretaker, an automated pull request is opened for maintainer review. The deprecation takes effect once a maintainer merges it.

If validation fails, edit the issue and comment `revalidate` to retry.

## How to delete an asset {#how-to-delete}

Deletion uses its own form (**Issues** > **New Issue** > **Delete an Asset**) with the same flow and authorization rule as deprecation, plus a required acknowledgement that the action is permanent.

Deleting an _already-deprecated_ asset is allowed: it makes the deprecation permanent. The reverse is not: a deleted asset can never go back to being merely deprecated.

:::deprecated

**Deletion cannot be undone.** There is no restoration flow, and maintainers will not restore deleted content. If you may ever want the asset back, deprecate it instead. Deprecation gives you everything deletion does except the permanence.

:::

## Restoring a deprecated asset {#restoring}

Deprecation is reversible through the same flow: **Issues** > **New Issue** > **Remove Asset Deprecation**. The same authorization rule applies. Once the resulting pull request is merged, the asset returns to normal: downloadable, visible in browse by default, exactly as before.

This flow only works for deprecated assets. Deleted assets are refused.

:::tip

If the problem is that _older versions_ of an asset no longer work on current game versions, [capping those versions' game compatibility](/registry/docs/manifest-requirements#retroactive) is usually the better fix than deprecating the whole asset.

:::
