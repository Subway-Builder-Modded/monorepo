Deprecation lets you retire an asset without deleting it. A deprecated asset:

- can **no longer be downloaded or installed** from Railyard or the website;
- is **hidden from browse and search results by default** — it remains viewable behind the **Deprecated** filter, marked with a gray badge and always sorted last;
- **keeps everything else permanently**: the listing page, its download history, and your author attribution. Download counts stay credited to you.

Deprecation is not deletion, and it is fully reversible.

## Who can deprecate {#who-can-deprecate}

Only the asset's **original publisher** or its **active [caretaker](/registry/docs/caretakers)** can deprecate it (or reverse a deprecation). Ordinary [collaborators](/registry/docs/collaborators) cannot.

## How to deprecate an asset {#how-to-deprecate}

1. On the [Registry's GitHub repository](https://github.com/Subway-Builder-Modded/registry), navigate to **Issues** > **New Issue** > **Deprecate an Asset**.
2. Enter your **asset ID** — the form works for both mods and maps, so no type selection is needed.
3. Optionally provide a **reason** (e.g. "Superseded by my-asset-2"). It is shown publicly on the asset's listing page.
4. Submit. After validation confirms you are the publisher or active caretaker, an automated pull request is opened for maintainer review. The deprecation takes effect once a maintainer merges it — allow a few hours after that for the change to reach Railyard and the website.

If validation fails, edit the issue and comment `revalidate` to retry.

## Restoring a deprecated asset {#restoring}

Deprecation is reversible through the same flow: **Issues** > **New Issue** > **Remove Asset Deprecation**. The same authorization rule applies. Once the resulting pull request is merged, the asset returns to normal — downloadable, visible in browse by default, exactly as before.

:::tip

If your asset's problem is that *older versions* no longer work on current game versions, you probably want to [cap those versions' game compatibility](/registry/docs/manifest-requirements#retroactive) instead of deprecating the whole asset.

:::
