<ChangelogSection type="features">

- Driving paths are now served from the app via a sidecar file
  - Mapmakers can optionally provide a `driving_paths.json` which enables Railyard to serve the driving paths rendered when a user clicks on an individual population group in the game.
- Enabled the Railyard app to handle the new `Deprecated` listing state.
  - Listings that are deprecated are no longer downloadable, but are not auto-purged as `Deleted` listings are.

</ChangelogSection>

<ChangelogSection type="improvements">

- Added a `Show Deleted Listings` setting, off by default, for looking up a listing after it has been removed
  - Deprecated and deleted listings each now have their own unique icon, sort last when viewable, and cannot be newly installed.
- Added a `Status` filter covering all listing lifecycle states: Active, Deprecated, Deleted, and Local.
  - Browse defaults to Active only; Library in addition shows Deprecated and Local.
  - `Status` selections are unions and can be combined
- Retired and removed versions now appear in a listing's version history as **No Longer Available**
  - These are no longer downloadable but keep changelog, release date, and download count
- Added sorting by data quality, with tiebreaker fallbacks

</ChangelogSection>

<ChangelogSection type="bugfixes">

- Fixed deleted assets surviving in a profile until the following restart
- Fixed map updates failing when the map's city code changed
- Fixed a renamed `.app` bundle breaking game launch on macOS
- Improved performance in demand driving path handling; with sidecar serving and caching, the sim no longer needs to hold these paths in memory.

</ChangelogSection>

<ChangelogSection type="notes">

- Deprecation is reversible and leaves your installs alone; deletion is permanent and uninstalls the asset. See [Listing Status & Filters](/railyard/docs/latest/listing-status-and-filters) for what each state means.

</ChangelogSection>
